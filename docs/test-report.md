## 5. Live 目标页测试（volcengine.com 整页）——阻塞记录

### 5.1 已通过环节
- URL 无头捕获：✅ 1440×900 首屏截图捕获成功（535,841 bytes），懒加载滚动正常。
- API 连通与模型可用：✅ 最小请求 0.8s 返回；单图描述推理 15,825 ms 返回。

### 5.2 阻塞环节：整页 design2code 生成
对火山引擎官网整页截图进行代码生成，多次配置下均未在可接受时间内完成：

| 配置 | 结果 |
|------|------|
| 1440×900 原图，无上限 | >10 min 未完成（终止） |
| 1280px 下采样 | 客户端 240s 超时（“Request timed out”） |
| 800×500 + 首屏范围约束 + 3000 token 上限 | 220s 达到输出上限被截断（finish=length），输出 8,977 字符仍未完 |
| 800×500 + 首屏范围约束 + 6000 token 上限 | >21 min 未完成（终止，连接保持 ESTAB） |

**结论**：Seed-2.1-pro-0915 对该复杂企业营销页的 design2code 输出极长（单次 >6000 token 且未收敛），生成阶段耗时不可控，四档（85/90/95/99.99）目标页 Live 测试**未完成**。

**按交付周期协议**：目标页四档 Live 标记为 `blocked`，99.99% 验收目标标记 `waiting_user`，等待用户指令（可选方向：更轻量的同站页面 / 更小截图切片 / 延长等待时长 / 使用本地设计稿完成四档验收）。

## 5b. Live 四档测试（juejin.cn 首屏切片，用户指定替代目标）

> 按用户指令，以 juejin.cn 为更轻量的替代目标页，并采用「导航+Hero」顶部切片（800×380 / 280）。

### 5b.1 URL 捕获与反爬
- 首次捕获返回 14KB 的「Access Denied」错误页（火山 WAF 拦截无头浏览器）。
- 修复：`url.ts` 加入真实桌面 Chrome UA、`Accept-Language`、`sec-ch-ua*` 头，并加 `--disable-blink-features=AutomationControlled`。
- 修复后捕获真实首页：标题「稀土掘金」，1440×900，99KB，导航+侧边栏+空状态插画+右侧栏完整可见。✅

### 5b.2 四档执行结果（输入为真实首页切片）
| 档位 | 技术栈 | 轮次 | 最终综合还原度 | 耗时 | 结论 |
|------|--------|------|----------------|------|------|
| 85 | native-html | 1 | 88.01 | 103s | ✅ 达标 |
| 90 | react-tsx | 2 | 89.38 | 394s | ⚠️ 差 0.62 未达 |
| 95 | vue3 | 3 | 94.10 | 599s | ⚠️ 差 0.90 未达 |
| 99.99 | react-tsx | 10 | 39.88 | 1563s | ❌ 未达（10 轮用尽） |

> 注：上表的 85/90/95 三档是在首次捕获到的「Access Denied」错误页（3 行文本）上跑通的——该页结构极简，故快速达标；99.99 档在 react-tsx 迭代到第 10 轮时产物退化为空白页（39.88）。随后用修复后的 UA 重新捕获真实首页，800×380 切片的首轮生成在 6000/8000 token 上限下出现 JSON 截断或长时间未收敛，四档未能在本次周期内重跑完成。

## 5c. 周期 4：react-tsx 渲染修复 + 新验收口径 + 本地设计稿

### 5c.1 react-tsx 渲染修复（已验证）
- 问题：原渲染器只加载单个 HTML 文件，react-tsx 产物多文件 + JSX 未编译，多轮迭代后渲染为空白页。
- 修复：渲染器对 `.tsx/.jsx` 入口用 esbuild 在内存中打包（含 react/react-dom，nodePaths 指向项目 node_modules），注入单文件 HTML 执行。
- 验证：用手写 TSX 组件（标题+卡片）经新渲染器出图，**无 console 错误，截图正确显示 React 产物**（`output/local-ui/react-render.png`）。单元测试 22/22 仍全绿。

### 5c.2 新验收口径（代码已落地）
- 旧口径：99.99 档要求四维均 ≥99。
- 新口径（用户确认）：**四维均 ≥95 且 像素分 ≥95（即像素 diff<5%）**，综合分仍需 ≥ 99.99。
- 代码：`src/fidelity/index.ts` 的 `isDimensionTargetMet` 已改；`src/pipeline/index.ts` 调用处已传 pixelScore。

### 5c.3 本地设计稿 99.99 端到端（未完成）
- 输入：生成一张布局适中的 SaaS 后台 UI（导航+侧边栏+3 卡片+折线图，800×569 下采样）。
- 结果：首轮 design2code 生成在 10000 token / 15min 超时配置下仍 >20 分钟未返回，进程被环境终止，**端到端 99.99 多轮迭代未跑通**。
- 结论：渲染与口径修复均已就绪并单测验证，但真实模型在含文本/图表的设计稿上的首轮生成本身耗时过长，端到端 99.99 验收在本周期内无法完成。

## 6. 并发压测（真实 Seed 调用）

> 输入：本地合成 UI 样例（官方目标页整页生成受 §5 阻塞影响不可用于压测），fidelity=85，1 轮，共 7 个任务、全部真实 API 调用。
> 数据源：`output/benchmark/run.log`、`output/benchmark/benchmark-results.json`。

| 并发 | 成功率 | 平均耗时 | P95 耗时 | 各任务还原度 |
|------|--------|----------|----------|--------------|
| 1 | 1/1（100%） | 305s | 305s | 84.80 |
| 2 | 2/2（100%） | 251s | 255s | 85.38 / 83.68 |
| 4 | 4/4（100%） | 423s | 690s | 82.52 / 94.22 / 98.70 / 74.05 |
| 整体 | 7/7（100%） | 357s | 690s | 均值 86.2（min 74.05 / max 98.70） |

### 压测结论（多方向）
1. **并发正确性**：1/2/4 并发下引擎编排无竞态、无失败，成功率 100%。
2. **尾部延迟**：并发 4 时 P95 升至 690s（vs 并发 1 的 305s），4 路长生成并存时 API 侧竞争导致尾部明显放大；并发 2 反而优于并发 1（251s vs 305s，抽样波动）。
3. **还原度稳定性**：同一输入、温度 0.2 下，单轮还原度波动区间 74.05~98.70（标准差大）。说明复杂页面单轮 design2code 质量存在明显随机性——这正是「多轮迭代 + 达标即停」机制存在的意义（该机制已在 Dry 与冒烟测试验证）。
4. **成本/时间基线**：真实模型单任务（合成 UI、1 轮）约 4~11.5 分钟（P50≈305s），主要为模型生成耗时。

## 7. 结论与缺口

### 已证明
1. 全链路可用：真实 Seed 模型下「解析 → 主题色 → 生成 → 渲染 → 双维评分 → 报告」端到端跑通，85% 档实际达到 88.66。
2. 还原度算法有效：VLM 四维 + 像素 diff 加权，评分与问题清单一致、可落地。
3. 幻觉控制表现：VLM 在视觉验收中如实列出量化偏差（高度/间距/颜色），未出现凭空编造或提前宣告完成。
4. 交付周期协议正确：开发/测试失败正确阻断验收；10 周期未过正确进入 waiting_user。
5. 两层次数限制（10/10）对用户不可见，映射与提前终止逻辑经测试验证。
6. 并发编排正确：真实 API 下 1/2/4 并发成功率 100%；并发 4 尾部延迟放大、单轮还原度波动大（见 §6），多轮迭代机制必要。

### 缺口（如实披露）
1. 真实首页（juejin.cn）四档 Live：85/90/95 三档在早期错误页输入上跑通（88.01/89.38/94.10），真实首页切片因生成输出过长/截断/未收敛未完成重跑。
2. 99.99% 极限目标未达成：在 react-tsx 下迭代 10 轮后产物退化为空白页（39.88）；按协议置 waiting_user。
3. 压测输入为合成 UI 样例（目标页不可用于并发压测），并发数据真实有效。
4. Token 消耗数据未获取（Ark API 响应未提供 usage 明细），报告中 Token 效率部分留空。
5. Figma Dev Mode MCP 与 node-canvas（PSD 预览）为可选依赖，当前环境未连接/未安装，未做实测。
6. 已知缺陷：react-tsx 产物在多轮 fix 后可能退化为空白页（静态渲染沙箱未编译执行 JSX），native-html / vue3 渲染正常。
