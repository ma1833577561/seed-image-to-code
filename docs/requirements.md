# 需求文档（Requirements）

> 项目：seed-image-to-code
> 版本：v1.0.0
> 依据模型：Seed-2.1-pro-0915（API：`doubao-seed-evolving`，能力一致）

## 1. 背景与目标

基于 Seed-2.1-pro-0915 的多模态 Coding / VLM 能力，构建「设计资产转前端代码」Skill，覆盖从设计输入到可运行代码交付的完整闭环，用于 Seed 模型升级征集活动，验证新版模型在以下维度的真实提升：

- 多模态视觉理解（UI 密集元素、图纸、组件定位、主题色提取）
- Coding 工程能力（多文件项目、跨文件修改、端到端开发）
- Agent 长流程执行（任务规划、工具调用可靠性、不提前宣告完成）
- Token 效率（本地预解析降耗、达标即停）

## 2. 功能需求

### 2.1 输入支持

| 输入类型 | 格式 | 处理方式 |
|----------|------|----------|
| 位图 | PNG / JPEG / WebP | 本地提取尺寸与色板，直接传入视觉模型 |
| PSD | .psd | 图层解析（可选依赖），失败则提示导出 PNG |
| Figma | 链接 / IDE 内选中节点 | Dev Mode MCP 结构化解析（文档级说明），失败则降级为截图 |
| URL | http(s) 站点 | 无头浏览器截图（视口 1440×900，全页长截图，先触发懒加载） |
| 剪贴板 | 截图 | 一键粘贴（Web/IDE 端） |

### 2.2 目标技术栈

- 原生：HTML + CSS + Vanilla JS（可选 Tailwind）
- Vue 3：单文件组件（可直接运行的内联版本）
- React 18：TSX 写法（可直接运行的内联版本）

### 2.3 配置项

- 目标还原度：85% ~ 100%（支持 99.99% 极限目标）
- 还原度与迭代轮次映射（见 3.3）
- 高级模式：可手动指定迭代轮次（内部上限仍受 max_loop=10 约束）

### 2.4 产物输出

- 原图 / 原始素材保留，支持与成品对比
- 代码产物：实时预览、单文件/全量复制、源文件打包
- 质量报告：还原度（综合分 + 四维分项）、迭代记录、问题清单、主题色板、Token 消耗（可用时）

## 3. 非功能需求与硬性规则

### 3.1 两层次数限制（均对用户不可见）

| 层级 | 常量 | 值 | 说明 |
|------|------|----|------|
| 单任务内部闭环 | `SYSTEM_MAX_LOOPS` | 10 | 「生成→渲染→评分→修正」循环 |
| 开发-测试-验收周期 | `DELIVERY_MAX_CYCLES` | 10 | 「开发修复→测试→验收」外层交付流程 |

### 3.2 还原度评分

- 综合分 = VLM 语义分 × 60% + 像素 diff 分 × 40%
- VLM 分项：布局 30% / 色彩 25% / 排版 25% / 细节组件 20%
- 提前终止：达标；代码连续无变化；问题清单连续无变化

### 3.3 还原度-轮次映射

| 目标还原度 | 内部轮次 | 场景 |
|------------|----------|------|
| 85% | 1 | 快速原型 |
| 90% | 2 | 日常页面 |
| 95% | 3 | 正式交付 |
| 99.99% | 10（顶格） | 极限复刻 |

### 3.4 验收与停止

- 按还原度与页面复杂度分级验收，极限目标 99.99%。
- 开发-测试-验收总周期 ≤ 10；任一周期通过即 `completed`，结束等待下一步指令。
- 10 周期仍未达 99.99% → `waiting_user`，保留最佳产物，停止一切继续修改/测试/模型调用，等待用户指令。
- 禁止通过修改评分公式、跳过像素校验、删除问题项等方式制造达标结果。
